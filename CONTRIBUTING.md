# Contributing to Avocado Pricing Engine

This guide covers everything needed to work on the project locally — from
environment setup to running tests and submitting a change.

---

## Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Python | 3.11 | Other 3.x versions may work but are untested |
| Git | any | |
| Docker + Compose | any | Optional — only needed for containerised runs |

---

## Local Development Setup

```bash
# 1. Clone the repository
git clone https://github.com/pitelet222/pricing-engine.git
cd pricing-engine

# 2. Create and activate a virtual environment
python -m venv .venv

# macOS / Linux
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1
```

```bash
# 3. Install runtime dependencies
pip install -r requirements.txt

# 4. Install dev-only dependencies (pytest, ruff, pre-commit)
pip install -r requirements-dev.txt
```

> **Tip:** If you only want to run unit tests without the full ML stack
> (no LightGBM, no NeuralForecast, etc.), install just the CI-equivalent
> deps: `pip install fastapi pydantic pydantic-settings prometheus-client
> pandas plotly joblib pytest pytest-cov httpx ruff`

## Generating Model Artifacts

The API and dashboard both depend on pre-computed artifacts in `data/outputs/`
and a feature file in `data/processed/`. These are **not** committed to git and
must be generated by running the notebooks in order:

```
notebooks/
  01_eda.ipynb                  → raw data profiling (no output files)
  02_feature_engineering.ipynb  → data/processed/avocado_features.csv
  03_forecasting.ipynb          → data/outputs/forecast_future.csv
                                   data/outputs/conformal_pi_stats.csv
                                   data/outputs/region_label_encoder.pkl
  04_pricing.ipynb              → data/outputs/demand_model.pkl
                                   data/outputs/pricing_recommendations.csv
  05_uncertainty.ipynb          → data/outputs/uncertainty_pricing.csv
  06_explainability.ipynb       → data/outputs/shap_top_drivers.csv
```

```bash
# Launch Jupyter and run all notebooks in order
jupyter notebook
```

Or run the export script directly (after notebooks have been run once):

```bash
python scripts/run_pipeline.py
```

## Running Tests

### Unit tests — always runnable, no artifacts needed

```bash
pytest tests/ -m "not integration" -v
```

This covers:
- `test_schemas.py` — Pydantic model constraints
- `test_config.py` — Settings, auth, JSON formatter
- `test_rate_limit.py` — Sliding-window rate limiter
- `test_charts.py` — Plotly chart builders
- `test_loader_unit.py` — DataStore helpers (`_require`, `_build_series_meta`)

### Full test suite — requires model artifacts

```bash
# Run notebooks 01–06 first, then:
pytest tests/ -v
```

Integration tests (`@pytest.mark.integration`) load the DataStore via the real
lifespan and hit all API endpoints end-to-end.

### Coverage report

```bash
pytest tests/ -m "not integration" \
  --cov=src/api/schemas --cov=src/config --cov=src/api/auth \
  --cov=src/api/metrics --cov=src/api/logging --cov=src/api/rate_limit \
  --cov=src/dashboard/charts \
  --cov-report=term-missing
```

## Linting

```bash
ruff check src/ tests/ scripts/
```

Ruff is configured in `ruff.toml`. It enforces pycodestyle, pyflakes, isort,
and pyupgrade rules. The pre-commit hook runs it automatically on every commit.

---

## Pre-commit Hooks

```bash
# Install the hooks (one-time setup)
pre-commit install

# Run manually on all files
pre-commit run --all-files
```

After installation, `ruff --fix` runs on every staged Python file before a commit
is created. This catches formatting and import-order issues before they hit CI.

## Starting the API Locally

```bash
# Requires data/outputs/ to exist (run notebooks first)
uvicorn src.api.main:app --reload
```

- Interactive docs: http://localhost:8000/docs
- Health check: http://localhost:8000/health
- Prometheus metrics: http://localhost:8000/metrics

To enable API key authentication:

```bash
PRICING_API_KEY=your-secret uvicorn src.api.main:app --reload
# Then pass the key in every request:
curl -H "X-API-Key: your-secret" http://localhost:8000/series
```

## Project Conventions

### Code style
- Line length: 100 characters (enforced by ruff)
- Imports: sorted by isort (via ruff `I` rules)
- Comments: only when the *why* is non-obvious (not the what)
- No docstrings on trivial getters; full docstrings on public API functions

### Test markers
- Tests that require `data/outputs/` **must** be marked `@pytest.mark.integration`
- Tests that run without artifacts must have **no** mark — they run in CI automatically

### Pydantic models
- All request/response schemas live in `src/api/schemas.py`
- Each schema has a `json_schema_extra` example using real `Albany_conventional` data

### Artifact columns
- Expected column names for each CSV are documented in the `DataStore` class docstring
  inside `src/data/loader.py`
- If a notebook changes a column name, update `src/api/schemas.py` and `src/data/loader.py` first

## Submitting a Change

1. Create a feature branch: `git checkout -b feature/your-change`
2. Make your changes and add tests
3. Run unit tests and linting:
   ```bash
   pytest tests/ -m "not integration" -v
   ruff check src/ tests/ scripts/
   ```
4. Regenerate the OpenAPI spec if you changed any schema:
   ```bash
   python scripts/export_openapi.py
   ```
5. Open a pull request against `master`

CI runs automatically on every push and PR. The following must all be green
before merging: unit tests + coverage gate (≥ 90%), import sanity checks,
ruff linting, and OpenAPI spec freshness.
